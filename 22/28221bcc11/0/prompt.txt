## Ranked picks

**1. Orphan branch (e.g. `archy-history`) written through the Contents API, with a `concurrency:` group.**
- The data is permanent git history, stays tiny, and is free on any plan.
- It needs only `contents: write`, which a workflow can request with a `permissions:` block.
- Reads are unauthenticated on public repos, so the trend chart can fetch it from the raw URL or the Contents API.
- A concurrency group serialises the merges, and the `sha` check is a second safety net.
- An orphan branch is not the default branch, so it is usually outside branch protection and required status checks. Rulesets that target all branches could still block it; this is unconfirmed.
- `GITHUB_TOKEN` pushes are documented to not trigger new workflow runs, so `[skip ci]` is likely unnecessary (unconfirmed this session).
- Failure modes are a ruleset that blocks the branch, and a read-only token on forked PRs. Only merges write, so fork PRs are irrelevant.

**2. Release asset on one rolling `history` release.**
- It is permanent and publicly readable, and it survives branch rulesets because it is not a branch.
- The cost is that replacement is not atomic. A concurrency group is still needed, and replace-by-delete can lose data if a run dies mid-way.
- It is clean for readers but weaker than the branch for appends.

**Fallback: an Actions artifact with `retention-days` set to the maximum, plus a re-upload on every merge.**
- It works with zero setup and `GITHUB_TOKEN` only.
- Cross-run download needs a run-id lookup and a token, so a chain can break. [download-artifact](https://github.com/actions/download-artifact/blob/main/README.md)
- Expiry loses everything after 90 days (public) or 400 days (private) of inactivity, so this is a stopgap, not a years-long store.

## Reject

- **actions/cache:** keys are immutable, it is evicted after 7 idle days, and it is not readable outside CI. It is not durable.
- **Actions variables:** `GITHUB_TOKEN` cannot write them, and a PAT or App token breaks the minimal-permission requirement. They also have no compare-and-swap.
- **Pages:** it needs a paid plan for private repos and a full-site deploy per merge. That is high cost for one file.
- **Git LFS and Packages:** they add quota and rate-limit concerns for 300-byte rows with no benefit.
- **Gists and Wiki:** a PAT is required (Gist) or push permission is unclear (Wiki). Both add friction and have no concurrency advantage over a branch.
- **Issue or comment storage:** it is abusive, hard to parse, and overwrites on edit.
- **Job summary:** it is ephemeral and not queryable.
